1. Computación en la nube: conceptos

Cloud computing (computación en la nube)

Es un modelo que permite acceder a través de Internet y bajo demanda a recursos informáticos (servidores, almacenamiento, bases de datos, redes, software) que están en centros de datos de un proveedor. El usuario no compra ni mantiene el equipo físico: usa el recurso y paga según lo que consume.

Idea clave: "la nube" no es algo abstracto; son computadoras reales ubicadas en centros de datos de otra empresa, a las que accedemos por la red.
Guardar fotos en Google Drive, ver una serie en Netflix o usar Microsoft 365 desde el navegador.

Máquina virtual (VM)

Es una computadora simulada por software que funciona dentro de una computadora física (anfitrión o host). Tiene su propio sistema operativo (invitado o guest), CPU virtual, memoria, disco y red. Un programa llamado hipervisor reparte los recursos físicos entre varias VM.

En una computadora con Windows se instala VirtualBox y dentro se crea una VM con Linux Ubuntu.

Contenedor y API

Contenedor: paquete ligero que incluye una aplicación y todo lo que necesita (librerías, configuración) para ejecutarse. A diferencia de la VM, no lleva un sistema operativo completo: comparte el núcleo (kernel) del sistema anfitrión, por eso arranca en segundos y ocupa menos. Herramientas: Docker, Kubernetes (orquestador de contenedores).

API (Interfaz de Programación de Aplicaciones): conjunto de reglas que permite que dos programas se comuniquen. En la nube, casi todo se controla mediante APIs: crear una VM, subir un archivo o consultar una base de datos.

2. Roles del modelo de relación en la nube

Cliente final o consumidor

Persona u organización que usa los servicios de la nube. Elige el servicio, lo configura según sus necesidades, paga por él y es responsable de sus datos, usuarios y contraseñas.

Ej.: un colegio que usa Google Workspace para sus estudiantes.

Proveedor o prestador

Empresa que ofrece los recursos: construye y mantiene los centros de datos, el hardware, la red, la virtualización y garantiza la disponibilidad según un acuerdo de nivel de servicio (SLA).

Ej.: Amazon Web Services, Microsoft Azure, Google Cloud.

Modelo de responsabilidad compartida: el proveedor protege la nube (infraestructura física, red, hipervisor); el cliente protege lo que pone en la nube (datos, cuentas, configuraciones, accesos).

Otros roles reconocidos (NIST): intermediario o bróker (gestiona servicios entre cliente y proveedores), auditor (evalúa seguridad y cumplimiento) y portador o carrier (proveedor de conectividad).

3. Virtualización

Concepto

La virtualización es la tecnología que permite crear versiones virtuales (simuladas por software) de recursos físicos, como servidores, almacenamiento, redes o sistemas operativos. Así, un solo equipo físico puede ejecutar varios sistemas independientes al mismo tiempo. El software que lo hace posible es el hipervisor.

  • Hipervisor tipo 1 (bare metal / nativo): se instala directamente sobre el hardware. Ej.: VMware ESXi, Microsoft Hyper-V Server, Xen.
  • Hipervisor tipo 2 (alojado / hosted): se instala como un programa sobre un sistema operativo. Ej.: VirtualBox, VMware Workstation, Virtual PC.

Conceptos relacionados

Ventajas de la virtualización

  • Ahorro de costos: menos servidores físicos, menos energía y espacio.
  • Mejor aprovechamiento del hardware (un servidor pasa de usar 15 % a 70–80 % de su capacidad).
  • Aislamiento: si una VM falla o se infecta, no afecta a las demás.
  • Rapidez: crear un servidor nuevo toma minutos, no semanas.
  • Respaldo y recuperación: snapshots y copias de VM completas.
  • Pruebas seguras: laboratorios para probar software o malware sin riesgo.
  • Migración: mover una VM de un servidor físico a otro sin apagarla.

Rol de la virtualización en la nube

La virtualización es el cimiento de la computación en la nube. Gracias a ella el proveedor puede:

  • Dividir sus data centers en miles de recursos virtuales y compartirlos entre muchos clientes (multi-inquilino o multi-tenant) de forma aislada.
  • Entregar recursos bajo demanda y en minutos (autoservicio).
  • Aumentar o reducir recursos automáticamente (elasticidad).
  • Medir el consumo de cada cliente para cobrarle.

5. Computación en la nube: características, historia y usos

Características esenciales (NIST)

  1. Autoservicio bajo demanda: el cliente obtiene recursos sin hablar con nadie del proveedor.
  2. Amplio acceso a la red: se accede desde cualquier dispositivo con Internet.
  3. Agrupación de recursos (pooling): los recursos se comparten entre muchos clientes.
  4. Elasticidad rápida: crece o se reduce según la demanda.
  5. Servicio medido: se mide y se cobra el consumo real.

Historia

AñoHecho
1961John McCarthy propone que la computación podría venderse como un servicio público, igual que la electricidad.
1969Nace ARPANET, antecesora de Internet. J.C.R. Licklider imagina una "red intergaláctica" de computadoras.
1999Salesforce ofrece software empresarial a través de un sitio web (inicio del SaaS).
2006Amazon lanza AWS con S3 (almacenamiento) y EC2 (servidores virtuales). Google populariza el término cloud computing.
2008Google App Engine (PaaS).
2010Microsoft Azure disponible comercialmente. Nace OpenStack (nube de código abierto).
2011El NIST publica la definición oficial de computación en la nube (SP 800-145).
2014 en adelanteComputación sin servidor (serverless, AWS Lambda), contenedores, multicloud y servicios de inteligencia artificial en la nube.

Tipos de soluciones (modelos de servicio)

IaaS

Infraestructura como servicio: se alquilan servidores virtuales, redes y almacenamiento.
Ej.: AWS EC2, Azure VM.

PaaS

Plataforma como servicio: entorno listo para desarrollar y publicar aplicaciones.
Ej.: Google App Engine, Heroku.

SaaS

Software como servicio: aplicación lista para usar desde el navegador.
Ej.: Gmail, Microsoft 365, Canva.

Otros (XaaS)

FaaS (funciones/serverless), DaaS (escritorio), BaaS (respaldo), STaaS (almacenamiento), SECaaS (seguridad).

Ventajas

  • No hay que invertir en equipos: se pasa de gasto de capital (CAPEX) a gasto operativo (OPEX).
  • Acceso desde cualquier lugar y dispositivo.
  • Escalabilidad y elasticidad inmediatas.
  • Actualizaciones y mantenimiento a cargo del proveedor.
  • Alta disponibilidad y respaldos en varias regiones.
  • Colaboración en tiempo real.

Seguridad en la nube (introducción)

La seguridad se basa en la tríada CID: Confidencialidad, Integridad y Disponibilidad. Medidas básicas: autenticación multifactor (MFA), cifrado de datos, control de accesos por roles, copias de seguridad, monitoreo y cumplimiento de normas (ISO 27001, ISO 27017, ley de protección de datos). Recordar el modelo de responsabilidad compartida. (Se profundiza en los resultados de aprendizaje 2 y 3.)

6. Componentes computacionales en la nube

Los componentes básicos son: cómputo (servidores/VM/contenedores), almacenamiento, redes, bases de datos, virtualización (hipervisor), plataforma de gestión (consola, APIs) y servicios de seguridad. El usuario accede mediante un front-end (navegador, app) y el proveedor opera el back-end (data centers).

Características de los servicios en la nube

  • Bajo demanda y autoservicio.
  • Multi-inquilino (varios clientes comparten la infraestructura de forma aislada).
  • Escalables y elásticos.
  • Medibles (pago por uso).
  • Resilientes (redundancia, alta disponibilidad).
  • Regidos por un SLA (acuerdo de nivel de servicio, ej. 99,9 % de disponibilidad).

Ventajas

  • Reducción de costos iniciales.
  • Rapidez de implementación.
  • Escalabilidad.
  • Movilidad y trabajo remoto.
  • Seguridad física profesional del proveedor.
  • Continuidad del negocio.

Desventajas o inconvenientes

  • Dependencia de la conexión a Internet.
  • Dependencia del proveedor (vendor lock-in).
  • Menor control sobre la infraestructura.
  • Riesgos de privacidad y ubicación de los datos.
  • Costos que crecen si no se controla el consumo.
  • Caídas del proveedor afectan a todos sus clientes.

Opciones de contratación

OpciónDescripción

ModeloDescripciónVentajasDesventajasEjemplo

Otros modelos: nube comunitaria (compartida por organizaciones con intereses comunes, ej. universidades) y multicloud (uso de varios proveedores públicos).

Práctica — RA1

Actividad 1: Laboratorio de máquina virtual

  1. Instale VirtualBox (o use el de la sala).
  2. Cree una VM con 2 GB de RAM y 20 GB de disco e instale una distribución Linux ligera.
  3. Tome un snapshot, borre un archivo del sistema y restaure el snapshot.
  4. Anote: ¿qué es el host y qué es el guest? ¿Qué tipo de hipervisor usó?

Actividad 2: Cuadro comparativo

Elabore un cuadro comparando nube pública, privada e híbrida para una empresa costarricense (ej. una cooperativa, un hotel o un colegio). Justifique cuál modelo recomienda.

Autoevaluación

1. ¿Qué diferencia a un hipervisor tipo 1 de uno tipo 2?El tipo 1 se instala directamente sobre el hardware (ESXi, Hyper-V, Xen); el tipo 2 se instala sobre un sistema operativo (VirtualBox, Virtual PC).
2. ¿Por qué un contenedor arranca más rápido que una VM?Porque no carga un sistema operativo completo; comparte el kernel del anfitrión.
3. Mencione las 5 características esenciales de la nube.Autoservicio bajo demanda, amplio acceso a la red, agrupación de recursos, elasticidad rápida y servicio medido.
4. ¿Qué es un CPD?Centro de Procesamiento de Datos: instalación que concentra los servidores y equipos de red de una organización.
5. ¿Qué rol cumple el proveedor en el modelo de responsabilidad compartida?Protege la infraestructura física, la red y la capa de virtualización; el cliente protege sus datos, cuentas y configuraciones.
6. ¿Cuál modelo de despliegue combina recursos propios con recursos de un proveedor público?La nube híbrida.
